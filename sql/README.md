# SQL-скрипты для аналитики и отладки

### `active_vk_users_and_topics.sql`

**Назначение:** Формирует реестр всех активных VK-пользователей и их привязку к конкретным топикам в Telegram-форуме.

**Когда использовать:**
* Для получения актуального среза "живой" аудитории моста.
* Для проверки корректности маппинга: какой `vk_user_id` соответствует какому `message_thread_id`.
* При онбординге новых пользователей, чтобы убедиться, что топики создались.

**Как читать результат:**
* `registered_at` — дата и время получения согласия.
* Если `tg_topic_id` равен `NULL` при статусе `active`, значит, пользователь дал согласие, но топик в Telegram не был создан или сохранен (ошибка на этапе `/connect`).

### `revoked_consents_churn.sql`

**Назначение:** Выгружает список пользователей, отозвавших согласие, с расчетом времени их жизни в системе.

**Когда использовать:**
* Для анализа оттока (Churn rate) и удержания аудитории.
* При обработке жалоб: если пользователь пишет, что бот перестал отвечать, этот скрипт покажет факт отзыва согласия.
* Для оценки UX: помогает понять, на каком этапе пользователи уходят.

**Как читать результат:**
* `churned_at` — точное время отзыва согласия (`/disconnect`).
* `hours_active_before_churn` — время в часах между регистрацией и отпиской. Массовый отток с показателем близким к `0` сигнализирует о проблемах на этапе первого контакта или о спам-атаках.

### `stuck_and_failed_webhooks.sql`

**Назначение:** Находит сообщения, застрявшие в очереди или упавшие с ошибкой. Извлекает из JSONB-поля `payload` превью текста и ID отправителя.

**Когда использовать:**
* **Главный инструмент для отладки** при жалобах на недоставку сообщений.
* Для мониторинга здоровья воркеров очереди.
* Для выявления специфичных форматов данных, которые ломают парсинг.

**Как читать результат:**
* `state = 'failed'` и `attempts = 5` — сообщение окончательно упало. Смотрите `message_text_preview`, чтобы понять, какой контент вызвал сбой.
* `state = 'processing'` и старое время (`updated_at`) — воркер "повис" или упал без отправки сигнала об ошибке.
* `state = 'queued'` и старое время (`available_at`) — очередь не разбирается (бот "лежит" или уперся в лимиты API).

### `telegram_albums_debounce_analysis.sql`

**Назначение:** Анализирует работу механизма склейки альбомов (debounce) для входящих сообщений из Telegram. Группирует фото по `media_group_id`.

**Когда использовать:**
* Если пользователи жалуются, что альбомы из Telegram приходят в VK как отдельные сообщения.
* Для проверки, хватает ли задержки в 3 секунды (`TELEGRAM_MEDIA_GROUP_DEBOUNCE_SECONDS`), чтобы Telegram API успел прислать все фото.

**Как читать результат:**
* `photos_in_album` — количество фото, которое система смогла собрать в один альбом. Если число меньше реального, альбом "разрывается".
* `time_spread` — разница по времени между первым и последним фото. Если это значение превышает 3 секунды, логику debounce нужно корректировать (увеличивать таймаут в коде).
