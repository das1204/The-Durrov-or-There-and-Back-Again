# The Durrov, or There and Back Again

[![Python 3.12](https://img.shields.io/badge/Python-3.12-3776AB?logo=python&logoColor=white)](https://www.python.org/)
[![Flask](https://img.shields.io/badge/Flask-web%20service-000000?logo=flask&logoColor=white)](https://flask.palletsprojects.com/)
[![Render](https://img.shields.io/badge/Deploy-Render-46E3B7?logo=render&logoColor=111111)](https://render.com/)
[![Neon](https://img.shields.io/badge/Database-Neon-00E599?logo=neon&logoColor=111111)](https://neon.tech/)

Сервис пересылает сообщения между VK и Telegram. Для каждого пользователя VK
создаётся отдельная тема в Telegram-форуме.

## Функции

- Пересылает текст, фотографии, видео, GIF и документы в обе стороны.
- Создаёт отдельную тему Telegram для каждого пользователя VK.
- Поддерживает команды `/connect` и `/disconnect`.
- Сохраняет webhook-события в очереди PostgreSQL перед обработкой.

## Поток сообщений

Пользователь VK отправляет сообществу `/connect`. Сервис сохраняет согласие и
создаёт тему в Telegram-форуме. Владелец отвечает из этой темы. Новые сообщения
пользователя VK приходят туда же.

| Endpoint | Назначение |
| --- | --- |
| `POST /tg_webhook` | Принимает сообщения владельца из настроенного форума Telegram. |
| `POST /vk_callback` | Обрабатывает событие Callback API `message_new`. |
| `GET /healthz` | Проверяет конфигурацию сервиса. |
| `GET /readyz` | Проверяет конфигурацию и подключение к базе данных. |

PostgreSQL хранит согласия пользователей, связи с темами, очередь webhook-событий
и данные ограничения частоты отправки. Схема базы создаётся при запуске
приложения.

## Требования

- Python 3.12
- PostgreSQL
- Telegram-бот и супергруппа с включёнными темами
- Сообщество VK с включёнными сообщениями и Callback API
- Хостинг, доступный по HTTPS для webhook-запросов (манифест развёртывания
  рассчитан на Render)

## Конфигурация

Для локального запуска скопируйте `.env.example` в `.env`. На хостинге задайте
эти значения как секретные переменные окружения.

| Переменная | Описание |
| --- | --- |
| `TG_TOKEN` | Токен Telegram-бота. |
| `TG_OWNER_ID` | Числовой Telegram ID владельца, которому разрешено пользоваться мостом. |
| `TG_WEBHOOK_SECRET` | Секрет заголовка Telegram webhook. |
| `TG_FORUM_CHAT_ID` | Отрицательный числовой ID супергруппы Telegram с включёнными темами. |
| `VK_TOKEN` | Ключ доступа сообщества VK, используемый приложением. |
| `VK_GROUP_ID` | Числовой ID сообщества VK без префикса `club`. |
| `VK_CALLBACK_SECRET` | Секрет сервера VK Callback API. |
| `VK_CONFIRMATION` | Строка подтверждения VK Callback API. |
| `DATABASE_URL` | URL подключения к PostgreSQL. |

Все переменные обязательны. Не добавляйте `.env` или секреты в репозиторий.

## Развёртывание

[`render.yaml`](./render.yaml) описывает Python Web Service для Render: установку
зависимостей из `requirements.txt`, запуск Gunicorn и health check по `/healthz`.

1. Создайте базу PostgreSQL и получите URL подключения.
2. Создайте Render Blueprint из репозитория; при необходимости задайте сервису
   уникальное имя вместо шаблонного `NAME` в `render.yaml`.
3. Добавьте в настройки сервиса все переменные из раздела
   [«Конфигурация»](#конфигурация).
4. Выполните deploy и проверьте, что `/healthz` возвращает HTTP 200.
5. Зарегистрируйте публичные HTTPS endpoints сервиса в Telegram и VK.

`/healthz` проверяет обязательную конфигурацию. `/readyz` также проверяет
подключение к PostgreSQL.

## Настройка Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather) и задайте `TG_TOKEN`.
2. Создайте супергруппу, включите темы и добавьте бота администратором с правом
   управления темами.
3. Укажите Telegram ID владельца в `TG_OWNER_ID`, а отрицательный ID группы
   в `TG_FORUM_CHAT_ID`.
4. Создайте случайный секрет и задайте его в `TG_WEBHOOK_SECRET`.
5. После развёртывания зарегистрируйте webhook:

```bash
curl --fail-with-body --silent --show-error \
  --request POST "https://api.telegram.org/bot${TG_TOKEN}/setWebhook" \
  --data-urlencode "url=${PUBLIC_BASE_URL}/tg_webhook" \
  --data-urlencode "secret_token=${TG_WEBHOOK_SECRET}" \
  --data-urlencode 'allowed_updates=["message","callback_query"]'
```

`PUBLIC_BASE_URL` задаёт HTTPS-адрес сервиса без завершающего `/`. Статус
доставки webhook можно проверить методом Telegram Bot API `getWebhookInfo`.

## Настройка VK

1. Включите сообщения сообщества и создайте ключ доступа с минимально
   необходимыми правами для отправки сообщений и работы с медиафайлами.
   Задайте его как `VK_TOKEN`, а числовой ID сообщества укажите в `VK_GROUP_ID`.
2. В настройках Callback API добавьте адрес
   `https://<адрес-сервиса>/vk_callback`.
3. Задайте секрет Callback API в `VK_CALLBACK_SECRET`.
4. Укажите строку подтверждения в `VK_CONFIRMATION`, подтвердите сервер и
   включите событие `message_new`.

Для настройки Callback API может понадобиться отдельный административный ключ.
Не добавляйте его в переменные приложения. `VK_TOKEN` должен иметь только права,
необходимые для работы моста.

### Ограничение VK для видео

Для создания видеозаписи сервис вызывает `video.save`. VK может отклонить этот
метод для ключа сообщества с ошибкой 5 (`User authorization failed`). В таком
случае MP4 отправляется как скачиваемый документ. Просматриваемое видео в чате
возможно только если VK принимает загрузку как видеозапись; текущий запрос
связывает загрузку с настроенным сообществом.

Входящие видеосообщения VK пересылаются в Telegram как видео, если MP4-ссылку
удаётся получить из вложения или ответа VK API `video.get`. Если ссылка
отсутствует, в журнал записываются тип вложения и имена доступных полей для
диагностики формата события.

## Лимиты

- Текст: до 3 500 символов.
- Фото: до 10 МБ. Другие медиафайлы: до 20 МБ.
- Исходящие сообщения: до 10 в минуту и 1 000 в сутки.
- Неуспешные webhook-задачи повторяются до пяти раз с увеличивающейся задержкой.
- Telegram-альбомы собираются перед обработкой.

## Эксплуатация

- `GET /healthz`: проверка конфигурации.
- `GET /readyz`: проверка конфигурации и подключения к PostgreSQL.
- Логи приложения пишутся в стандартный вывод и доступны в панели хостинга.

При проблемах с доставкой проверьте логи сервиса и ответ `getWebhookInfo` в
Telegram. Состояние сервера и список событий Callback API доступны в настройках
сообщества VK.

## Безопасность

- Храните токены, секреты webhook и реквизиты базы только в защищённых
  переменных окружения.
- Используйте отдельные ключи для runtime-доступа и административной настройки.
- Ограничьте доступ к панелям хостинга и базы данных доверенными операторами.
- Отзовите и замените любой секрет, который мог быть раскрыт.
